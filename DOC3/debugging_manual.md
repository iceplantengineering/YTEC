# デバッグ手順書（REFACT3 + GATEWAY版）

本手順書は、REFACT3システム（4PLC構成 ＋ **M8001 シミュレーション/オフラインモード対応**）および **GATEWAY（Pythonプロセス）**の連動による、PC単体でのオフライン総合動作確認を行うためのものです。

> **背景と特徴:** 
> - M8001をONにすることで物理I/Oや異常状態をバイパスできます。
> - GATEWAYを用いることで、複数PLC間のデータリング（CC-Link仮想コピー等）とModbus/TCPのルーティングが自動化され、Luaアプリから実機レスでシームレスな結合テストが可能になりました。

---

## 1. 準備

### 1.1 PC環境
- [ ] Windows端末にて必要なLUAスクリプト、Redisサーバーが動作していることを確認する。
- [ ] **【変更】** Luaスクリプト（`TConEquipmentTest.lua`）のIPアドレスが、実機IPから **`127.0.0.1` ＋ GATEWAY用ポート（15021等）** へ変更されていること。
- [ ] GATEWAY構成ファイル（`GATEWAY/config.json`）の `station_number` が各GX Simulator2の局番と一致していること。

### 1.2 PLC（GX Simulator2）環境
- [ ] GX Works2（または3）にて、`REFACT3`フォルダ内の全プログラムを個別のGX Simulator2として起動しておく。
  - PLC-1（局番1想定）: `B01_GroundPanel_Q_Switch_GXW.asc` + `Masked_ST_Logic.st`
  - PLC-2（局番2想定）: `B02_GroundPanel_Q_Switch_GXW.asc` + `Masked_ST_Logic.st`
  - PLC-3（局番3想定）: `StackerCrane_Refactored_Q_Switch_GXW.asc`
  - PLC-4（局番4想定）: `Conveyor_Refactored_Q_Switch_GXW.asc`

### 1.3 ネットワークとGATEWAYの起動
- [ ] コマンドプロンプト等で `GATEWAY` フォルダへ移動し、`python main.py` を実行する。
- [ ] ログ上で「全PLCへMX Componentで接続成功」および「M8001がONに設定された」ことが確認できること。

## 2. タスク判定ロジック (ST言語) の確認

GATEWAY経由でB01/B02のSTロジック単独検証が可能です。

### 判定条件テーブル（B01/B02共通）

| ケース | 入力: D339 (Src) | 入力: D340 (Dest) | 期待値: D330 (TaskType) |
|---|---|---|---|
| A. 入庫 | 0より大 | 0 | **100** |
| B. 出庫 | 0 | 0より大 | **200** |
| C. 移動 | 0より大 | 0より大 | **300** |

- 手順：Modbus/TCPクライアント（またはLuaのテストスクリプト）から、`127.0.0.1:15021` (B01) の `D339` 等に値を書き込み、PLCモニタ上で `D330` を確認します。

## 3. PC単体での連動シーケンスデバッグ手順

GATEWAYが `cc_link_copy.py` によりPLC間の通信（CC-Link信号やU2\Gデータ）を代行するため、手動でフラグを操作しなくても自動でシーケンスが進みます。

### 3.1 準備・初期化
1. GX Simulator2で4台のPLCが動作しており、GATEWAYプロセスも実行中（`M8001=ON`）であることを確認する。
2. アラームデバイス `D456` 等に異常が残っている場合は、異常リセット（`X74` のON等）でクリアする。

### 3.2 搬入タスクの発行〜自動連動
1. LuaまたはテストツールからB01へ `D339` = `1001` (搬入元), `D340` = `0` (搬出先なし) を書き込む。
2. `D330` = `100` になる。
3. **【自動化】** コンベヤ側のシミュレーションタイマーが満了すると、GATEWAYのBデバイスコピー機能によりB01側で `M1063` 等がONし、`D212` (搬入受取可) が成立する。
4. **【自動化】** GATEWAYが `D212` や `D330` 等をスタッカーへ転送（CC-Link/U2\G仮想コピー）。
5. **【自動化】** スタッカーがタスク実行を開始し、完了すると完了通知が発行される。

---

## 4. Modbus/TCP通信・全体結合テスト

実機配線を一切必要とせず、上位システムを含めたフル結合テストが可能です。

1. **Luaスクリプトの起動**: タスクキュー（Redis）を監視するLuaプロセスを起動する。
2. **WMSからのタスク投入**: Redisの `taskInfo` リストへ通常のタスクJSONをLPUSHする。
3. **連動確認**:
   - LuaがJSONを解析し、GATEWAY宛（127.0.0.1）に指示を出す。
   - B01/B02にてSTロジックが走り、コンベヤとのハンドシェイクが成立。
   - スタッカーへ転送され、仮想シミュレーション内でタスクが完了し、最終的にRedis等へ完了信号が返ってくることを確認。

## 5. トラブルシューティング

| 症状 | 原因 | 対処 |
|------|------|------|
| GATEWAYがMX Componentで接続エラーを吐く | 局番設定の不一致等 | `config.json` の `station_number` と、GX Simulator2立ち上げ時の論理局番が合っているか確認してください。 |
| デバイステストで手動ONしたフラグがすぐ戻る | GATEWAYのコピーによる上書き | `cc_link_copy.py` が周期的に元デバイスの値をコピーして上書きしています。手動でテストしたい場合はGATEWAYを一時停止してください。 |
| STKが待機状態から動かない | データがコピーされていない | GATEWAYがU2\G空間（D3000~等）へのコピーを正しく行っているか、ログを確認してください。 |
