# デバッグ手順書（REFACT3版）

本手順書は、REFACT3システム（B01/B02地上盤PLCを分割した4PLC構成 ＋ **M8001 シミュレーション/オフラインモード対応**）の動作確認を行うためのものです。

> **REFACT3の特徴:** 
> - M8001をONにすることで、コンベヤや安全機器などの周辺ハードウェアが存在しなくても、または異常状態（CC-Link断線など）であっても、通信やインターロックをバイパスしてPLC内部のソフトウェアロジックのみを単独で検証（オフラインデバッグ）することができます。

---

## 1. 準備

### 1.1 PC環境
- [ ] Windows端末にて必要なLUAスクリプト、Redisサーバーが動作していることを確認する。
- [ ] Modbus/TCP通信に必要なライブラリ（`socket`, `TClientHelper`）が使用可能であること。
- [ ] B01/B02それぞれのIPアドレスが設定されていること。

### 1.2 PLC環境
- [ ] GX Works2/3にて、`REFACT3`フォルダ内のプログラム（`.asc`, `.st`）が各PLCに書き込まれているか確認する。
  - PLC-1: `B01_GroundPanel_Q_Switch_GXW.asc` + `Masked_ST_Logic.st`
  - PLC-2: `B02_GroundPanel_Q_Switch_GXW.asc` + `Masked_ST_Logic.st`
  - PLC-3: `Conveyor_Refactored_Q_Switch_GXW.asc`
  - PLC-4: `StackerCrane_Refactored_Q_Switch_GXW.asc`

### 1.3 ネットワークとテストモード選択
- [ ] 対象のPLCとEthernet経由で通信でき、Pingが通ることを確認する。
- **【重要】デバッグモードの選択:**
  - **実装モード:** 実機（センサ、モータ、CC-Link接続）が存在し、物理的に動作させる場合 ➔ **M8001 を OFF（デフォルト）**
  - **オフラインシミュレーションモード:** 実機が未接続、または机上デバッグのみを行う場合 ➔ GX Worksのデバイステスト機能を使って **M8001 を強制 ON** にする。

---

## 2. タスク判定ロジック (ST言語) の確認

`Masked_ST_Logic.st` がB01/B02それぞれのPLCで正しく機能するか確認します。
オフラインモード（M8001=ON）であれば、通信異常等に妨げられることなくSTロジック単体の検証が容易です。

### 判定条件テーブル（B01/B02共通）

| ケース | 入力: D339 (Src) | 入力: D340 (Dest) | 期待値: D330 (TaskType) |
|---|---|---|---|
| A. 入庫 | 0より大 | 0 | **100** |
| B. 出庫 | 0 | 0より大 | **200** |
| C. 移動 | 0より大 | 0より大 | **300** |

## 3. M8001 オフラインモードによる単体デバッグ手順

周辺機器レスで一連の動作シーケンスをテストする手順です。

### 3.1 準備・初期化
1. GX Works で対象のPLC (例: B01) をモニタ・書込モードにする。
2. デバイステストで **`M8001` を ON (SET)** する。
   ➔ これにより、電源入(X60)や準備完了、CC-Link正常(M370等)、安全機器(X80系)がすべて**強制的に正常状態**になります。
3. `D456` (アラームコード) が `0` であることを確認。もし異常値があれば異常リセット `X74` をON/OFFしてクリア。

### 3.2 搬入タスクの発行シミュレーション (B01 例)
1. Modbus/TCP（または直接デバイステスト）で、`D339` = `1001` (搬入元), `D340` = `0` (搬出先なし) を書き込む。
2. `D330` = `100` (入庫タスク) に自動で変わることを確認。
3. `M3831` (連動PC有一_タスクタイプ搬入) などがONになることを確認。

### 3.3 コンベヤからのハンドシェイク（受取可）シミュレーション
REFACT3ではPLC側にコンベヤとのハンドシェイクロジックが追加されています。これをテストします。
1. B01の場合、コンベヤCV1の「リフタ上限」と「在席」を擬似的に成立させるため、以下のCC-Link受信用Mデバイスを強制ONします。
   - `M1063` (CV1_搬入リフタ上限: B3F相当) -> ON
   - `M1057` (CV1_搬入ST在席: B39相当) -> ON
2. B01がスタッカー(STK)に「搬入受取可」を通知するレジスタ **`D212` (B01入庫搬入受取可) が `1` になること** を確認します。

### 3.4 搬出タスクのハンドシェイク (受渡可) シミュレーション
1. 出庫タスクとして `D339` = `0`, `D340` = `1001` 等を設定し、`D330` = `200` になることを確認。
2. 出庫先のコンベヤが空であることを擬似的に作ります。
   - `M1079` (CV2_搬出リフタ上限: B4F相当) -> ON
   - `M1073` (CV2_搬出ST在席: B49相当) -> **OFF** (在席していない)
3. B01がスタッカーに「搬出受渡可」を通知するレジスタ **`D214` (B01入庫搬出受渡可) が `1` になること** を確認します。

## 4. Modbus/TCP通信・結合テスト

オフラインシミュレーション（M8001=ON）を利用して、Lua側から実機なしでWMSシステム全体の結合テストを行うことができます。

### 4.1 B01/B02個別接続確認
- [ ] B01 PLC / B02 PLCの M8001 をONにしておく。
- [ ] LuaからTCP接続を行い、接続成功することを確認。
- [ ] LuaからRedis経由でタスクをLPUSHし、正常にLuaからModbus経由でPLCの D339/D340 に反映されるか確認。

### 4.2 シーケンス進行のテスト
- コンベヤ側PLCやスタッカー側PLCも M8001 をONにすることで、センサ入力やモータ駆動時間をタイマーで擬似的に消化し、自動で完了ステータスへ遷移させることが可能です（全PLCオフラインモード）。

## 5. トラブルシューティング

### 5.1 シミュレーション時 (M8001=ON) のトラブル

| 症状 | 原因 | 対処 |
|------|------|------|
| M8001=ONなのにアラームが出る | リセット未実施 | M8001立上りパルスで一部アラームは消えますが、ラッチされているものは異常リセット(X74)が必要です。 |
| デバイステストでM1057等がONできない | M8001バイパスによる強制上書き | M1057等の通信先Mリレーはシミュレーション対象外だった場合、プログラムスキャンで上書きされる可能性があります。「Bデバイス空間(B39等)」をONにするかプログラムを確認してください。 |
| STKが動かない(シミュレーション) | STK側のM8001がOFF | 全システムを連動シミュレーションする場合は、STK・コンベヤもM8001をONにしてください。 |

### 5.2 実装時 (M8001=OFF) のトラブル
REFACT2と共通です。通信断線やセンサ異常など、ハードウェア起因のエラーを確認してください。
