# デバッグチェックリスト（REFACT3 + GATEWAY版）

> **REFACT3構成:** B01地上盤/B02地上盤/コンベヤ/スタッカーの4PLC構成。
> PC内で統合テストを行うため、**M8001（シミュレーションモードフラグ）** と **GATEWAY（Modbus/仮想CC-Linkプロセス）** を併用します。

---

## 1. 事前確認

### 1.1 ソフトウェア・ネットワーク環境
- [ ] Redis Serverが起動していること (`redis-server.exe`)
- [ ] Luaスクリプト（`TConEquipmentTest.lua`）のIPアドレスが対象環境に合わせて設定されていること
  - 実機： `192.168.1.xxx`
  - PC内テスト： `127.0.0.1` (ポート15021等)
- [ ] GATEWAY構成ファイル（`GATEWAY/config.json`）の局番(`station_number`)がGX Simulator2での設定と一致していること。

### 1.2 PLCプログラム書込・起動確認
- [ ] PLC-1（B01地上盤）が起動していること (`B01_GroundPanel_Q_Switch_GXW.asc` + `Masked_ST_Logic.st`)
- [ ] PLC-2（B02地上盤）が起動していること (`B02_GroundPanel_Q_Switch_GXW.asc` + `Masked_ST_Logic.st`)
- [ ] PLC-3（コンベヤ）が起動していること (`Conveyor_Refactored_Q_Switch_GXW.asc`)
- [ ] PLC-4（スタッカー）が起動していること (`StackerCrane_Refactored_Q_Switch_GXW.asc`)

---

## 2. デバッグモードの選択と起動確認

### 2.1 実機実装モード (Physical Mode) の場合
- [ ] 全てのPLCの `M8001` が **OFF** であることを確認する
- [ ] CC-LinkやI/Oの物理配線が正常であることを確認する。

### 2.2 オフラインシミュレーションモード (PC単体テスト) の場合
- [ ] Pythonプロセスとして `python main.py`（GATEWAY）を起動する。
- [ ] GATEWAYのログに「Mx Component接続成功」が表示されること。
- [ ] GATEWAY起動により、全PLCの `M8001` が自動的に **ON** になったことをGX Worksのモニタで確認する。
- [ ] `D456` 等に残存アラームがある場合はリセット (`X74`等) を行う。

---

## 3. タスク制御ロジックとハンドシェイクの確認 (GATEWAY経由) 

※ GATEWAY起動中は、CC-Link信号が自動コピーされるため、手動でデバイスをON/OFFする必要はありません。

### 3.1 B01 動作確認
- [ ] Lua側から `D339` = 1001, `D340` = 0 を送信 ➔ タスク種別 `D330` = **100** になるか。
- [ ] コンベヤシミュレータのタイマー経過後、自動的に `M1063` 等がONし、`D212` (受取可) が **1** になるか。
- [ ] GATEWAYが `D212` やタスク情報をスタッカーへ自動転送し、スタッカーが動作を開始するか。

### 3.2 B02 動作確認
- [ ] Lua側から `D339` = 0, `D340` = 1001 を送信 ➔ タスク種別 `D330` = **200** になるか。
- [ ] スタッカーがB02へ荷物を搬送し、完了するとB02の対応フラグが自動でONに切り替わるか。

---

## 4. 運用結合テスト 

- [ ] WMS(Redis)に搬入・搬出タスク（`cmd:101`, `cmd:102` 等）を複数LPUSHする。
- [ ] Luaスクリプトがタスクを順次処理し、GATEWAY経由でPLCへ指示を行うか。
- [ ] 仮想シミュレーション内で荷物が搬送先のステーションまで到達し、自動連動して完了ステータスがRedisに返却されるか。

### 4.2 トラブルシューティング
- [ ] ルーティングエラー：Luaスクリプトのポート番号とGATEWAYのポート番号（config.json内）が一致しているか。
- [ ] コピー未反映：GATEWAYの画面で `cc_link_copy.py` によるエラースタックトレースが出ていないか。
- [ ] 状態リセット：途中で動作がおかしくなった場合は、GX Simulator2で対象PLCをリセットし、再度GATEWAYを再起動する。
