#### 4.1.4 Masked_ST_Logic.st（STロジック）

**機能概要:**

ST言語で記述されたタスクタイプ判定ロジック。Source StationとDestination Stationの状態からタスクタイプを判定します。

```st
IF (D339 > 0) AND (D340 = 0) THEN
    D330 := 100; // 搬入
ELSIF (D339 = 0) AND (D340 > 0) THEN
    D330 := 200; // 搬出
ELSIF (D339 > 0) AND (D340 > 0) THEN
    D330 := 300; // 移庫
END_IF;
```

| 変数 | 説明 |
|------|------|
| D330 | タスクタイプ出力（100=搬入, 200=搬出, 300=移庫） |
| D339 | Source Station ID（起点局番号） |
| D340 | Destination Station ID（終点局番号） |

## 5. 通信構成比較

### 5.1 refact版の通信アーキテクチャ

```
┌─────────────────────────────────────────────────────────────────┐
│                        WMS (上位システム)                        │
└───────────────────────────┬─────────────────────────────────────┘
                            │ Modbus/TCP
                            ↓
┌─────────────────────────────────────────────────────────────────┐
│           制御PC (Lua: TTask.lua, TConEquipmentTest.lua)        │
└───────────────────────────┬─────────────────────────────────────┘
                            │ Modbus/TCP
                            ↓
┌─────────────────────────────────────────────────────────────────┐
│           GroundPanel PLC (地上盤) - マスター制御                 │
└───────┬───────────────────────────────────────────┬─────────────┘
        │ CC-Link IE           │ MC Protocol
        ↓                       ↓
┌───────────────┐       ┌───────────────┐
│ Conveyor PLC  │       │ StackerCrane  │
│  (B01/B02)    │       │     PLC       │
└───────────────┘       └───────────────┘
```

### 5.2 通信方式一覧

| 通信経路 | プロトコル | 主なデータ |
|---------|-----------|-----------|
| PC ↔ 地上盤PLC | Modbus/TCP | タスク情報、ステータス |
| 地上盤 ↔ コンベアPLC | CC-Link IE | 制御データ、RFIDデータ |
| 地上盤 ↔ スタッカーPLC | MC Protocol | タスク情報、座標データ |
| コンベアPLC ↔ AGV | 光伝送 | 発進可信号 |

## 7. 改善・向上点

### 7.1 アーキテクチャの改善

| 改善点 | 詳細 |
|--------|------|
| **ロジックのPLC移管** | タスク種別判定ロジックをLuaからPLC（ST言語）に移管し、PCレス運転を可能に |
| **ST言語導入** | 複雑な判定ロジックをST言語で記述し、可読性・保守性を向上 |
| **通信明確化** | Modbus/TCP、CC-Link、MC Protocolの役割を明確に定義 |

### 7.2 セキュリティ向上

| 改善点 | 詳細 |
|--------|------|
| **タスクタイプ隠蔽** | TTask.luaでTaskTypeをマスクし、PLC内で判定することで上位システムでの情報漏洩リスクを低減 |
| **起点/終点局番号による判定** | SrcStation/DestStationのみを送信し、PLC側でタスク種別を推定 |

### 7.3 保守性向上

| 改善点 | 詳細 |
|--------|------|
| **ドキュメント整備** | `doc/`フォルダにシステム構成図、信号表、デバッグ手順書を追加 |
| **コード構造化** | 各PLCプログラムを機能ブロック単位に分割 |
| **エラーハンドリング** | TRedis.luaでpcallを使用した安全な操作 |

### 7.4 運用柔軟性向上

| 改善点 | 詳細 |
|--------|------|
| **単独運転モード** | PCレスでHMIから直接タスク発行可能 |
| **多様な運転モード** | 手動、自動単独、自動連動（PC有/無）に対応 |
| **管理者モード** | パスワード認証による安全機器一時解除機能 |

## 8. 注意事項・推奨事項

### 8.1 TConEquipmentTest.luaの変更について

**変更内容:** 第141行の`con_in.requestY = 1`がマスクされている

**影響:**
- RFID読み取り後のリクエストフラグが設定されない
- WMSへの重複通知防止機能が無効化されている可能性

**推奨事項:**
- この変更の目的と影響をドキュメント化すること
- requestYフラグが設定されないことによる副作用をテストすること

### 8.2 移行時の注意点

| 項目 | 注意点 |
|------|--------|
| **PLCプログラム** | refact版の.asc/.stファイルをPLCに書き込む必要がある |
| **通信設定** | CC-Link、MC Protocolのパラメータ設定が必要 |
| **タスクフロー** | タスクタイプ判定がPLC側で行われるため、Lua側のTaskType送信をマスクする必要がある |

## 9. 結論

### 9.1 互換性評価

| 項目 | 評価 |
|------|------|
| **Luaプログラム** | ほぼ完全互換（99.9%） |
| **通信プロトコル** | 完全互換 |
| **機能カバレッジ** | refact版がPDF回路図を実装した形 |

### 9.2 改善評価

| 改善点 | 評価 |
|--------|------|
| **アーキテクチャ** | PLC主体の制御への移行により、PCレス運転が可能に |
| **セキュリティ** | タスクタイプ隠蔽による情報漏洩リスク低減 |
| **保守性** | ドキュメント整備とコード構造化により大幅に向上 |
| **運用柔軟性** | 多様な運転モードと管理者モードの実装 |

### 9.3 総合評価

refactフォルダのプログラム群は、origineフォルダの機能を完全に包含しつつ、以下の点で大幅な改善が見られます：

1. **PCレス運転の実現**: PLC側でタスク判定を行うことで、PCダウン時も単独運転が可能
2. **セキュリティ向上**: タスクタイプ情報の隠蔽
3. **保守性向上**: ドキュメント整備とコード構造化
4. **運用柔軟性**: 多様な運転モードの実装

origine版からrefact版への移行は、上位システム（WMS）とのインターフェースが変わらないため、比較的スムーズに行えると考えられます。
